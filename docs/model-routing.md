# Capability-aware model routing

SPILTON routes intent before selecting a provider. `CapabilityModelRouter` receives capability requirements and asks the provider resolver only for models that are actually configured. Provider metadata declares general, coding, reasoning, research-synthesis and vision support, a context bound, latency class and cost class. These are operational declarations, not quality scores.

The current compatible provider is the only real transport when its private server configuration is complete. The deterministic development provider is visibly labelled as a demo. No model is synthesized into the list. Process-local health records consecutive transport/rate-limit failures without recording prompts or credentials and clears after success. With one configured real provider there is no meaningful cross-provider fallback yet.
